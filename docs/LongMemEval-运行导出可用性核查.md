## 必须保留的证据边界

- L0 的 `textOriginal` / `textIndexed` 是按数据集与原适配器规则恢复的文本输入，不是原生 MemoryRecord 快照。embedding、衰减状态、检索计数等未保存字段不能补造。
- L1 节点来自冻结图谱；低置信度、推断或误抽取要原样显示。该批案例没有 L1 语义关系边。`evidence_link` 是根据 evidence 构造的展示连线。
- 21 组同题同轮的 A/B 上下文哈希完全相同，B 的 `queryL1` 均为 0。因此这些成功结果不能证明 L1 查询内容带来提升。C 在上下文中加入首回合画像，但本批数据仍不足以证明画像有因果收益。
- `qa_complete.json` 中只有 focused108 的正式问答单元。导出包提到的紧预算文本构造不能称为已执行的 budget32 问答。
- 调用和评分是离线实验档案；没有现场工具执行轨迹，也不是 DSH 在线服务或 OSWorld 经验复用记录。`judge` 标签是导出包的评分声明，未在本轮重新评分。
- 本轮文件清单校验只能确认导出文件相互一致；未取得原始实验输入环境来独立核验来源、模型调用或完整 108 题结果。

## 接入建议

先为这批数据做独立的“LongMemEval 运行档案”只读入口，按“问题与组别 → L0 来源 → L1 节点及证据连线 → 检索与上下文 → reader 回答与 judge 标签”展开。案例默认显示选择偏差与来源说明；缺失字段显示“未保存”，不能以 0 代替。A/B/C 的上下文和结果并排比较时，应明确 A/B 在本批案例中相同。

现有“经验快照”导入器只接受插件的 `ExperienceSnapshot v1`，此导出包不是该结构；现有 MOCK 数据检查也应与本档案分开。实施时宜新增适配器和本地只读导入，先核对案例、引用与文本转义，再考虑经审查的公开样本。原始数据不随本次文档上传，也不直接加入 GitHub Pages。
