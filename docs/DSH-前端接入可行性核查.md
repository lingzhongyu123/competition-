# Memory Console 在 DSH 前端打开：可行性核查

> 2026-10-25 最新进展：用户已提供 dsh-advanced-mem-plugin 仓库，已核对 0.3.0 / DSH 0.2.1-rc.2 的兼容基线、原生配置页入口、Memory 程序接口和 OSWorld bridge。详见 [源码核查与接入清单](Memory插件-源码核查与接入清单.md)。下文“资料未取得”描述的是此前核查时点；当前仍未完成真实 DSH/Memory 联调。

2026-10-25。针对“做成 DSH 插件、直接从其前端打开；有条件时让 DSH 更有麒麟风格”的探索。这里只检查现有 Console 和本地交接材料，不绘制系统架构图。

## 已取得的事实

- 当前仓库是独立 Web 原型；根目录 `双击打开演示.html` 是含样式、数据和脚本的单文件。另有本地 HTTP 入口。尚无 DSH 源码、版本、插件 SDK、宿主页面或登录/CSP 配置。
- Console 当前直接写入 `#app`，使用 `document.body` 设置模式和主题，读取/修改当前窗口的 hash 路由，基础 CSS 有 `body` 等全局选择器。因此不能把现有脚本和 CSS 原样注入 DSH DOM，就宣称是原生插件。
- 本地创建一个普通同源宿主页，通过 iframe 加载根目录演示；浏览器中两条 OSWorld 故事能切换，iframe 内 URL 从 `#osworld?story=reuse` 变为 `#osworld?story=formation`，宿主页地址不变。这只验证浏览器嵌入方式，**没有验证 DSH 本身**。

## 目前的判断

| 路径 | 当前判断 | 得到 DSH 后需验证 |
|---|---|---|
| DSH 提供前端插件/页面扩展接口 | 未知；当前没有插件包 | 插件 SDK、路由和菜单注册、组件生命周期、资源基址、主题与权限接口 |
| DSH 允许宿主页面嵌入 iframe | 浏览器同源原型可行；DSH 未知 | 宿主 CSP `frame-src`、页面 `frame-ancestors`、同源部署、登录态、通信协议、窗口尺寸 |
| DSH 前端源码可改 | 未知 | 所用框架、构建与发布方式、导航入口、页面容器及升级维护责任 |
| DSH 不提供扩展也不可改 | 继续用独立 Console | 能否从 DSH 菜单打开外部页面，由负责人确认 |

短期可准备“同源内嵌”的接入试验，因为独立页面已能在普通宿主中工作。真正选择插件、iframe 或路由改造，必须以 DSH 的实际资料为准。若用 iframe，还需确定 Console 如何只读获取工作区/主题信息，以及 host 和 frame 的消息来源校验；现在没有实现这些交互。

## 麒麟风格的范围

当前 Console 已有浅色标题栏、浅灰侧栏、蓝色选中态，是受麒麟公开视觉启发的概念样式。它不会自动修改 DSH 外层导航或其他页面。若 DSH 提供设计 token 或主题接口，可以先把 Console 的颜色、字体和间距与之映射；若要调整 DSH 整体前端，须先确认源码、许可范围、设计要求和发布责任。现阶段不能声称已完成 DSH 换肤，也没有麒麟官方 UI 规范授权。
